# Decisions

Product and engineering decisions, with the options considered and why. Newest last.

| # | Decision | Options | Choice and reason |
|---|---|---|---|
| D-001 | Language of the core | Rust; TSX with Rust helpers | **Rust for everything but screens.** The core (S3, credentials, jobs, probes, decoders) is testable without a UI and survives a UI change; TSX holds presentation only. |
| D-002 | Native Shell version | crates.io 0.4.0; a git commit | **`longbridge/nsh` at commit `beeb9fc`** (0.4.0 + main), in `Cargo.toml` (`rev = …`) and in CI's nsh install (`NSH_REV`). The CLI must match the crates it links; a commit pins both. |
| D-003 | SigV4 | `aws-sigv4`; our own | **Our own (`s3raw::sigv4`, ~150 lines)**, tested against the AWS SigV4 test suite and the S3 documentation's examples. It exposes the canonical request and string to sign, which a diagnosis tool wants, and handles `STREAMING-UNSIGNED-PAYLOAD-TRAILER` and deliberate clock skew for probes. |
| D-004 | HTTP | `reqwest` + rustls; hyper | **reqwest with rustls and native roots**: custom CAs per endpoint, no OpenSSL (static-libc binaries). Redirects are not followed: a 301/307 is a finding (wrong region / addressing). |
| D-005 | Where the listing lives | rows in JS; rows in Rust | **Rust (`Listing` class)**; TSX asks for the visible window. 100 000 rows never cross into the VM. |
| D-006 | Rust ↔ TSX types | typed `JsObject` structs; JSON | **JSON (`JsonValue`) mirrored by `app/src/types.ts`.** Deriving NSH traits on core types would make `sonde-core` depend on NSH, which the layering forbids; a second set of structs in `sonde-nsh` would duplicate every type. |
| D-007 | Static keys in the UI | a form field; config file only | **Config file only.** A key typed into TSX would pass through the JS VM; static keys are for local test servers and live in `config.toml` (0600). |
| D-008 | Destructive confirmation | a checkbox; typed text | **Typed text**: the number of items (many) or the bucket name (one item, lifecycle). Plans expire in 10 minutes and run once. |
| D-009 | Hermetic UI tests | mock in TSX; a server | **A demo S3 server in `sonde-core::demo`** (in-process, 127.0.0.1): real HTTP through the real client, with versions, delete markers, uploads, 100 000 synthetic keys and the real decoder samples. It doubles as `sonde tui --demo`. |
| D-010 | The terminal host | `nsh run --target tui` / `nsh-tui-host`; our own loop | **Our own loop on `nsh-platform-tui`** (FINDINGS #2): one binary embeds the bundle, takes sonde's CLI arguments, and the four places of the app. |
| D-011 | Plugin views in the macOS app | a custom AppKit host; degrade | *(Superseded by D-031.)* **Degrade the presentation**: `nsh package --target macos` builds NSH's runner, which hosts one app; the app manages plugins and opens their views in `sonde tui`. The plugin mechanism (verification, trust, revocation, sandbox) is the same. |
| D-012 | Plugin capability policy | trust the package; check | *(Superseded by D-031.)* **Check at install**: only `host` calls under `sonde.read.*`; any other key must grant nothing (`nsh publish` writes every key). Checked again when a plugin opens. |
| D-013 | Second S3 implementation for CI | Ceph RGW; Garage; SeaweedFS | **Ceph RGW (`ceph/daemon demo`)** as the spec asks, plus **RustFS** (MinIO-compatible, starts in seconds) in CI; MinIO is optional (D-023). |
| D-014 | Iceberg sample | hand-written JSON/Avro; pyiceberg | **pyiceberg 0.9.1** (`tools/gen_iceberg.py`): a real table with appends, an overwrite, a delete, an orphan and expirable snapshots. |
| D-015 | Woodpecker sample | a running Woodpecker; its codec | **Woodpecker's own codec** (`tools/gen-woodpecker`, Go, module at commit 3a8ce69) laying objects out as its object-storage writer does; running Woodpecker needs etcd and MinIO, which CI has no reason to host. |
| D-016 | lakeFS commits | parse KV dumps; trees only | **Trees only**: commits live in lakeFS's KV store, not in the bucket; each metarange is shown as a committed tree, and the UI says so. |
| D-017 | Closed formats | heuristics; cadence only | **Cadence only** for turbopuffer and WarpStream, with "format not published, not decoded" in the UI. |
| D-018 | Probe verdict "differs" vs "fail" | — | **fail** when a guarantee breaks (a condition ignored, a wrong checksum accepted, wrong bytes); **differs** for other statuses or shapes (409 for 412, uuid version ids). |
| D-019 | Exit codes | 0/1; graded | **Graded** (docs/cli.md): CI can fail on broken guarantees (1) and still report differences (2). |
| D-020 | Linux binary | musl; glibc on an old base | **glibc, built on Ubuntu 22.04** (glibc 2.35): only libc/libm/libgcc_s; QuickJS's C build is untroubled; runs on Debian 12 slim (checked in CI). |
| D-021 | Config path on macOS | `~/.config/sonde`; Application Support | **`~/Library/Application Support/sonde`**, the platform's convention; `$SONDE_CONFIG_DIR` and `$XDG_CONFIG_HOME` override on both. |
| D-022 | App capabilities | `fs` for exports; none | **`clipboard`, `notifications` (a run ended) and `windows` (a session in its own window)**: Rust writes every file; the VM needs no `fs` or `network`. |
| D-023 | Integration targets in CI | MinIO + Ceph RGW + RustFS; Ceph RGW + RustFS | **Ceph RGW + RustFS**: MinIO stopped publishing public images (Docker Hub and Quay refuse anonymous pulls), so its job could not start. `scripts/integration.sh minio` still runs it with `MINIO_IMAGE` set to an image you can pull. |
| D-024 | macOS runners | macos-13 / macos-14; macos-15 / macos-15-intel | **macos-15 (arm64) and macos-15-intel (x86_64)**: the older images never got a runner. |
| D-025 | Direction for 1.0 | a findings dashboard over bucket state; the traffic between an application and its store | **The traffic.** sonde's edge is protocol truth (raw exchanges, SigV4, vendor behavior, layout decoding); a cost advisor over bucket state competes with the cloud's own tools. 1.0 records what software does (`sonde run`), explains it (operations, not requests), and replays it on other endpoints. Bucket scans stay, as one more source of requests. |
| D-026 | How the recorder sees requests | an HTTPS MITM proxy with a local CA; an S3 endpoint that re-signs | **A local S3 endpoint that re-signs.** No CA to install, no TLS interception, and the application never holds the real credentials (it gets dummy keys; sonde signs). Signed `aws-chunked` bodies are decoded because their chunk signatures chain from the client's key; presigned URLs are re-signed. |
| D-027 | 404 on GET/HEAD in summaries | errors; their own count | **Their own count ("not found")**: stores probe for keys that do not exist yet (SlateDB looks for the next manifest and WAL this way, 116 of its 172 requests in the sample run). Counting them as errors would make every healthy run look broken. |
| D-028 | Replay | re-send recorded bytes; re-enact requests | **Re-enact.** Sessions keep no object data (size, privacy) and endpoints hand out their own upload ids, ETags and tokens, so replay sends synthetic payloads of the recorded length, keeps control documents, maps identifiers as it goes, and confines every key to a fresh prefix. Comparing status and S3 code catches what matters for correctness — a conditional write that should have failed, a missing feature — without false alarms from ETag or timing differences. |
| D-029 | Direction for 2.0 | more sections; one place to start | **Run is the home.** Typing a command and watching its terminal next to its operations is the shortest path to sonde's point; the session that results holds both, lined up in time. Everything else is reached from it. |
| D-030 | Navigation | nine sections in a sidebar; a few places and a palette | **Four places (Run, Sessions, Store, Settings) and a command palette.** The bucket tools live under Store as tabs, configuration and logs under Settings; every place, tab and action is in the palette (⌘K, `:` in the terminal). |
| D-031 | Plugins | keep; remove | **Remove.** Signed packages, trust roots and revocation cost a screen, a CLI group and a sandbox to explain, and their views could open only in the terminal (the macOS runner hosts one app). Layout decoders stay built in; supersedes D-011 and D-012. |
| D-032 | The program's output | a log file next to the session; in the session | **In the session** (`{"log": …}` lines with arrival times), so one file carries what was printed and what was requested, and alignment needs no second clock. |
| D-033 | Sharing a session | a hosted service; a static site | **A static site** (`sonde share`): the viewer built with Native Shell's web target from the app's pure views, and a document computed in Rust. No Rust in the browser, nothing to run, any host. |
| D-034 | Desktop platforms and updates | macOS only; macOS, Linux, Windows | **macOS, Linux (GTK 4) and Windows**, one TSX app, built by CI. Updates through Native Shell's updater from GitHub Releases (`latest.json`, SHA-256 checked), only when the user asks. |
| D-035 | The look of 2.1 | restyle screens one by one; a design system first | **A design system first**, as Native Shell's design guide asks: semantic tokens for what sonde shows (request outcomes, storage formats, the toolbar, the inspector), one icon family (Lucide on a Canvas, in token colors), the app's own styled layer on nsh/base (Tabs, Tooltip, Toast, Sheet, AlertDialog, Collapsible, Combobox, Tree, Command, DataTable's parts), then the pages from it. |
| D-036 | Where details go | a third fixed column; pages; an inspector | **An inspector**: a resizable panel beside what it details (an operation, a request, an object), closed from its bar; in a narrow window it comes in from the edge as a Sheet and the sidebar folds away, so the table keeps its room. |
| D-037 | The window's chrome | the system's title bar; the app's own | **The app's own** (`titleBar: hidden`): one toolbar for where you are, the program running, the endpoint, the lock and search, instead of a title bar and a header repeating each other. On Linux and Windows, whose menu bar goes with the system's title bar, the toolbar has a menu button (`Menu.popup`). |
| D-038 | Saving settings | a Save button; as they change | **As they change**, a toast with Undo: a setting is a decision already made when it is changed. |
| D-039 | A visual check | screenshots by hand; in CI | **In CI**: `scripts/shots.sh` drives the app on a real GTK window under Xvfb through every place, wide and at the least size, light and dark, English and Chinese; the PNGs are each build's artifact. Behavior tests cannot see a clipped column or an unreadable header. |
